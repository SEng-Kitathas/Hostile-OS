# Cross-Project Quarry Ledger

This ledger is **ore classification**, not architecture. Every row is one of: `LAW/PROCESS`, `CANDIDATE`, `SCAR`, `REJECTED`, or `CONTAMINATION`.

## FtD distributed organism

**Class:** CANDIDATE + SCAR-bearing donor.  
**Strong transfers:**
- ECS as internal representation; role derived from present capability rather than permanent class.
- Recursive holons as complexity firewalls: constituent handles internal detail and exposes compact semantic/capability surface upward.
- Dynamic recomposition after damage: changed component set changes phenotype/role; compatible survivors may form a replacement organ.
- Resource economy skeleton: supply -> demand -> priority -> reserve -> allocation.
- Asynchronous semantics: use UNKNOWN/stale/probationary rather than pretending disconnected state is false or current.
- Native-capability orchestration: substrate already computes valuable things; orchestrate rather than reproduce.
- Local reflex + higher-order awareness: latency-sensitive response need not wait for global deliberation.

**OS pressure:** hardware engines (MMU, DMA, NIC offloads, NVMe queues, timers, interrupt controllers, GPU, cryptographic instructions) should be treated as candidate native accelerators/oracles, not automatically wrapped in heavyweight software replicas.

**Scar:** FtD is a constrained game substrate. Mechanisms must be re-derived against real hardware, adversarial programs, privilege, persistence, and compatibility.

## Aedifex-Bellator / Genesis-Omega

**Class:** LAW/PROCESS + contrary witness.

**Strong transfers:**
- genotype/governance != expression/configuration != phenotype/current capability != lifetime/history != environment/substrate;
- lifetime adaptation cannot silently rewrite governing law;
- mature-state injection forbidden; capability must re-earn operational authority after restoration;
- causal authorship: action issued != outcome observed != self-caused outcome;
- capability self-claims are candidates until probed/calibrated/promoted;
- bounded non-scalar executive arbitration; exact replay and long-horizon adversarial campaigns.

**Contrary witness:** Aedifex retained an explicit seeded multi-timescale scheduler and compute-homeostasis windows. Scheduler elimination is therefore not assumed; it must beat an explicit scheduler under matched requirements.

## Microseed

**Class:** LAW/PROCESS + CANDIDATE.

**Strong transfers:**
- composition first; emergent useful wholes can become reusable parts;
- emergent capability allowed, emergent authority forbidden;
- candidate lifecycle: propose -> qualify externally -> admit -> reuse;
- currentness/drift/context distinctions;
- consequence-side learning from actual outcomes;
- bounded operational frames and episode/biography continuity;
- language labels are inspection vocabulary, not ontology;
- no planner/scheduler/manager primitive by naming the problem.

**OS pressure:** process/file/service/driver/scheduler may be useful phenotypes, not primitive species.

## PAL

**Class:** LAW/PROCESS + SCAR.

**Strong transfers:**
- evidence independence and provenance ancestry;
- query-relative authorization/use licensing;
- currentness, reliability, authorization, feasibility are different;
- anonymous negative-space alternatives can challenge exhaustive claims without being asserted true;
- same nondiscriminating repetition cannot solve identification;
- `DiscriminationNeed`: know what evidence must separate alternatives even when no executable experiment yet exists.

**OS pressure:** a clean workload corpus cannot prove scheduler/resource allocator completeness if hostile workload classes remain behaviorally equivalent under the tested regime.

## CIC / NERV

## HSP / Loop+ / OARR / PDVER / Semantic Helix / Attention Reservoir

**Class:** GOVERNING PROCESS.

This project uses this stack rather than inventing a new R&D process. HSP is the whole R&D operating system. Loop+ expands; OARR attacks; PDVER couples research and embodiment to reality; the Helix preserves what was learned; the Reservoir preserves breadth and deferred fronts.

## Genome / CSC

**Class:** ASSURANCE PROCESS.

Current useful form is restrained: target-aware profiles, machine-readable obligations, known-good/bad/near-miss/false-positive discrimination, lineage anchors, evidence findings, explicit coverage ceiling, audit-only authority.

**Rejected:** older universal pattern/proof rhetoric that makes the checker sovereign or claims broad soundness without target discrimination.

## Ergo-Light / VoidStar / Chainwraith

**Class:** CANDIDATE + SCAR.

**Strong transfers:**
- runtime leverage may be purchased offline: expensive discovery/layout/codegen can emit compact deterministic runtime artifacts;
- memory layout may follow observed co-use/access topology rather than conceptual taxonomy when it pays;
- logical holon boundary != process boundary; isolation must buy enough to cover serialization/context-switch/coordination costs;
- adaptive scar cache: repeated expensive misses may earn bounded hot artifacts, but require eviction/decay/context/budget;
- resource asymmetry: spend abundant CPU/build-time/storage to preserve scarce GPU/VRAM/runtime only when Pareto-justified;
- generated replay need only preserve causal structure relevant to the test, not pixel identity.

**Scars:**
- same cardinality != same topology;
- same vector position != same entity identity;
- numeric hygiene must not silently change domain semantics;
- alignment declarations != serialized alignment;
- unkeyed hash != authentication;
- rollback attempt != atomicity;
- deterministic control flow != bit-deterministic numerics;
- `FINAL` != evidence;
- descendant restatement != independent corroboration.

## KarnOS / Holonix / SYNAPSE / KSL / FASM

**Class:** HEAVY CONTAMINATION + quarry.

This lineage is directly ancestral to the present OS intuition and therefore cannot be treated as an independent confirmation.

**Useful ore:**
- `PROBE -> DERIVE -> EMBODY -> RECURSE` substrate adaptation;
- capability-selected dispatch from measured hardware properties;
- hardware-near data structures and fixed-point/low-bit candidates;
- proof obligations/forbidden transitions at low-level interfaces;
- fault isolation/supervision and append-only evidence ideas;
- energy as first-class resource;
- state reconciliation rather than ceremonial startup sequence;
- data locality and NUMA/batching pressure;
- actor/message-passing and capability security as candidates.

**Contamination:**
- schedulerless stigmergic coordination was already proposed;
- ECS/holonic OS architecture was already proposed;
- a Holonix branch retained an ECS scheduler; both sides of scheduler question exist in ancestry.

**Scars/rejections:**
- XOR/parity/address binding != security/correctness;
- redundant peers != reconstruction authority without sufficient code/redundancy;
- lower opcount != Landauer-limit proof;
- ternary representation != physical 1.58-bit cost;
- Hilbert locality != security;
- label `aerospace grade` != assurance;
- drafted function != implemented/compiled/correct;
- Landauer was overused as instruction-cost oracle;
- architecture specification massively outran embodiment.

## Rust ECS theoretical-limits audit

**Class:** CANDIDATE + SCAR.

**Useful ore:**
- every abstraction pays rent;
- begin from bandwidth/cache/NUMA/latency/energy realities;
- hot-path allocation and pointer-chasing require evidence;
- one ECS storage form is not universal: stable/archetypal and volatile/sparse data can need different layouts;
- SoA/SIMD only when access pattern justifies it; inspect generated machine behavior;
- broad mutable world authority is suspect; granular read/write contracts;
- CRDT/monotonic/tombstone patterns are candidates for distributed state.

**Scar:** HFT-style busy-spin and thread-per-core choices are local points on a Pareto frontier, not universal OS law.

## Cognitive Field Engineering (CFE/CEF candidate)

**Class:** CANDIDATE PROCESS/REPRESENTATION DONOR.

Recovered candidate laws:
- curator-named mechanism != learner-required ontology;
- surface diversity != field coverage;
- multi-turn != long-horizon interaction topology (LHIT);
- long context != causal depth;
- compiler/projection layer must not dominate the phenomenon it is meant to expose;
- test ontology leakage, reification, coverage claims, overload, temporal leakage and paradigm dependence.

**OS pressure:** a large event log or huge component graph is not automatically causal coverage; developer naming of an object does not prove the runtime needs that object as native ontology.
