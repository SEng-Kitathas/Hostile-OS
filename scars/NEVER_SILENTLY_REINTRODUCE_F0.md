# Never Silently Reintroduce - HOSTILE-OS

Any resurrection requires an explicit discriminator addressing the original failure or contamination.

Do not silently reintroduce:

- `Scheduler`, `ProcessManager`, `ServiceManager`, `DriverManager`, `FilesystemManager`, `ArbitrationManager`, `ReentryManager`, `UncertaintyEngine`, `GoalManager` merely by naming the problem;
- schedulerless stigmergy because KarnOS once proposed it;
- ECS/holons because FtD/Holonix/Microseed made them attractive;
- global ternary state; use three-valued semantics only where UNKNOWN is real;
- global append-only everything; retention must serve an explicit CONTROL/REPAIR/AUDIT purpose;
- CIL as universal semantic filesystem/brain;
- TQ2/ternary as physical compression or energy proof without hardware/encoding evidence;
- Hilbert/space-filling locality as security or universal layout law;
- branchless/thread-per-core/busy-spin/zero-syscall as universal performance law;
- fixed numerical `optimal` thresholds from CogOS/GODSPEC ancestry;
- Landauer limit as instruction-cost oracle;
- hash/parity/address binding as correctness/authentication/security proof;
- same cardinality as same topology;
- same vector/index position as identity;
- rollback attempt as atomicity;
- deterministic control flow as bit-deterministic cross-host numerics;
- one process per holon or one holon per process; logical and protection boundaries are different questions;
- microservices/process separation where isolation does not pay for serialization/context-switch/coordination cost;
- UI/presentation as semantic or execution authority;
- cached/historical hardware/service capability as current after reboot/restart;
- source/event/commit/model IDs as evidence independence;
- descendant project restatement as corroboration;
- cross-project resemblance as shared architecture;
- test green as external truth;
- `FINAL`, `SEALED`, `production-ready`, `aerospace-grade`, `Omega`, or similar labels as evidence;
- simulation or emulation success as proof of physical hardware behavior without the appropriate boundary;
- old rejected mechanism through a new name;
- research result automatically mutating the main implementation;
- CSC/assurance code in runtime authority unless explicitly earned;
- exact current state from narrative handoff when hashes/logs/runtime disagree;
- naive scientific foreground launch without durable logging and post-run inspection;
- silent split between source and deployed/derived runtime;
- unlimited event/journal/cache growth without purpose-relative economics;
- the idea that smaller is always better: Pareto law permits extra burden when it buys real capability;
- the inverse idea that capability excuses arbitrary bloat: marginal burden must buy a qualified nondominated property.
