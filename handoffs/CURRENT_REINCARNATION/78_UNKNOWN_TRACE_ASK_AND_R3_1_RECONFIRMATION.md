## 1. New escalation rule

When a load-bearing point is unclear, unknown, contradictory, partly visible, or present only through traces whose meaning/origin cannot be established:

1. inspect durable project evidence first;
2. separate verified, inferred and unknown state;
3. if the load-bearing unknown remains, **ASK the commander** before crossing it;
4. if traces of an artifact, decision, dependency, prior action, external input or state cannot be identified from durable evidence, **ASK** rather than treating the trace as understood;
5. do not ask the commander to reconstruct information that Git/project continuity already contains;
6. bounded non-destructive information-buying action is allowed only when it cannot alter load-bearing state or destroy evidence.

Compact form:

> **Inspect first. If a load-bearing unknown remains, ASK. If you see traces you cannot identify, ASK. Never guess across the gap.**

## 2. Relationship to zero-re-explanation

The two rules cover opposite sides of the same boundary:

- **known/persisted state:** rehydrate it yourself; asking the commander to retell it is a continuity failure;
- **genuinely unresolved load-bearing state after inspection:** ask the commander; guessing is a control failure.

Therefore:

`ZERO_REEXPLANATION != NEVER_ASK`

and:

`INSPECT_FIRST + ASK_AT_REAL_UNKNOWN_BOUNDARY = CONTROLLED_CONTINUITY`
